# Server Storage Directory (`server-data/`)

## Storage Purpose & Architecture

This directory is strictly reserved for physical binary and media file uploads generated by the RES-Q-TRACK system:
- **`uploads/captures/`**: Resident biometric ID card PNG captures and facial recognition reference snapshots.
- **`uploads/reports/`**: Incident scene photos, vehicular damage captures, and citizen-submitted accident report attachments.

---

## Enterprise RDBMS Migration Notice (Zero SQLite Retention)

> **IMPORTANT**:
> Local SQLite database persistence (`resqtrack.db`, `resqtrack.db-shm`, `resqtrack.db-wal`) has been **permanently decommissioned and purged**.
> This directory contains **ZERO** SQLite database files.

Relational data persistence is managed exclusively via enterprise RDBMS:
1. **Primary Database Engine**:
   - **Microsoft SQL Server (SSMS 19 / SQL Server 2019/2022 / LocalDB / Express)**
   - Managed via Entity Framework Core (`Microsoft.EntityFrameworkCore.SqlServer`).
   - Connection strings are configured via `appsettings.json` / `appsettings.Development.json` (`ConnectionStrings:DefaultConnection`) or environment variables.
2. **Alternative Enterprise RDBMS Options**:
   - **PostgreSQL** (`Npgsql.EntityFrameworkCore.PostgreSQL`)
   - **MariaDB / MySQL** (`Pomelo.EntityFrameworkCore.MySql`)

---

## Directory Integrity

- Do **not** commit local database binaries or personal test files into this directory.
- File system permissions should grant read/write access to the ASP.NET Core backend process for serving and storing uploaded media in `uploads/`.
