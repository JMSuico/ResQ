# ID OCR IMPLEMENTATION DECISIONS -- ARCHITECTURAL DECISION RECORD (ADR)

## ADR-ID-01: Template-, Version-, and Side-Aware Recognition Before Field Extraction
- **Decision**: Never run field extraction or form autofill until the uploaded image has passed through `DocumentQualityAnalyzer`, `IdTypeClassifier`, `IdSideClassifier`, and `IdVersionClassifier`.
- **Rationale**: Different Philippine IDs -- and different versions/sides of the same ID family (e.g., LTO Old Restriction-Code vs. LTO 2021+ DL-Code, PhilSys PVC vs. Paper ePhilID vs. Digital ID, PhilHealth Card vs. MDR Document) -- place fields in different spatial regions and use different label anchors.
- **Fallback**: When classification confidence is below threshold (`< 0.45`), classify as `UNKNOWN` (`needsManualTypeSelection: true`) and never force-route the image through the LTO or PhilSys parser.

## ADR-ID-02: Elimination of All Sample-Specific Hardcoded Mutations
- **Decision**: Remove all hardcoded sample-specific overrides in `idScanWorker.ts` (`yyyy === '2008' || '2009' || '2000' || '2006' -> '2004'`, `2004/02/20`), `textExtractor.ts` (`yyyy -> '2004'`), and `validators.ts` (`I/1/T/3/9 -> J`, `0Z -> 07`, `88/80/68 -> 60`).
- **Rationale**: Overfitting to a single test card corrupts real civilian and responder data across Katipunan, Zamboanga del Norte and the Philippines. OCR ambiguity must be handled via multi-threshold consensus, format validation, and `REQUIRES_REVIEW` status rather than silent value replacement.

## ADR-ID-03: ROI-First Extraction Precedence Over Whole-Card OCR
- **Decision**: Template-aligned ROI extraction (`RegionOcrService` / `idScanWorker.ts`) is the primary VIZ extraction channel for card layouts. Whole-card anchor parsing (`dynamicAnchorParser.ts`) is restricted to supplementing missing fields (`!existingField`) or handling variable-layout LGU/document templates (`document` side), and must **never** overwrite a validated ROI field or run front-side heuristics on a `back` image.
- **Rationale**: Whole-card binary thresholding (`val < 135 ? 0 : 255` in `onDeviceWasmOcr.ts`) destroys colored guilloche security backgrounds and previously overwrote clean ROI crops.

## ADR-ID-04: Machine-Readable Channels (MRZ / QR / PDF417 / Barcode) Cross-Check VIZ
- **Decision**: When a document contains a machine-readable zone (Passport ICAO 9303 TD3 MRZ, PhilSys QR, LTO back barcode/serial, PRC/OWWA/Postal/PWD 2026 QR), parse both the machine-readable channel and the VIZ, compute check digits where defined (ICAO 9303 `7-3-1` Modulo-10), and compare overlapping fields via `FrontBackConsistencyChecker`.
- **Rationale**: Prevents front/back mix-ups (uploading Front of Person A and Back of Person B) and catches OCR character substitutions in VIZ names, dates, and ID numbers.

## ADR-ID-05: Strict Separation of 5 Verification Dimensions & Calibrated Confidence
- **Decision**: Remove all artificial confidence floors (`Math.max(..., 0.68 / 0.78 / 0.88)`). Every extracted field carries an `ExtractedField<T>` provenance envelope with calibrated confidence (`0.0` to `1.0`) and explicit status:
  - `ACCEPTED_FOR_PREFILL`: `confidence >= threshold` AND format/semantic validation passed AND no front/back conflict.
  - `REQUIRES_REVIEW`: extracted text exists but has low/medium confidence, OCR cleanup warning, or cross-check discrepancy.
  - `NOT_EXTRACTED`: no text extracted (`confidence = 0`).
- **Verification Separation**:
  1. **OCR Extraction Status**: Were characters read and parsed?
  2. **Document Format & Consistency Status**: Did regex, date logic, check digits, and front/back consistency pass?
  3. **Official Issuer Verification Status**: Checked against PSA/LTO/PRC/DFA/NCDA official registry (`not_checked` / `pending_official_check` when offline).
  4. **Facial Biometric & Liveness Status**: Live camera 4-pose challenge vs. ID portrait (`FaceVerified`).
  5. **Account Approval Status**: LDRRMO Admin governance (`AccountStatus.Pending`).

## ADR-ID-06: Data Minimization & NCDA AO No. 001 (2026) PWD Privacy Protection
- **Decision**:
  1. **PhilSys**: Extract and prefill only the 16-digit public **PhilSys Card Number (PCN)**; never store or expose the internal PhilSys Number (PSN) in registration prefill.
  2. **PWD ID (Legacy LGU & Sept 9, 2026 NCDA AO No. 001 Unified PWD ID)**: Exclude disability type, severity, cause, and functional limitations from registration autofill (`excludedSensitiveFields`), and set `allowBiometricProfiling: false` so the PWD card facial image is never used for automated facial profiling without an explicit alternate verification path.
  3. **Solo Parent / Voter / MDR**: Extract only identity, address, and document control fields needed for emergency dispatch registration.

## ADR-ID-07: Swapped 6-Phase Registration Order, Visible-Only Claude Vision OCR & Shared Model Failover Chain
- **Decision**:
  1. **Swapped 6-Phase Order**: `01 Role -> 02 Gov ID Upload & Visible-Only Claude Vision OCR (#phase-2-id-upload) -> 03 Personal & Address Info (#phase-3-personal-info) -> 04 Facial Record -> 05 Account Credentials -> 06 Review & Submit`.
  2. **Visible-Only Zero-Fabrication Policy**: Return `null` (Backend) / `""` (Frontend) for any field not visibly printed on the uploaded ID image(s). Never invent placeholder PII (`JUAN`, `DELA CRUZ`, `1995-05-15`, `Poblacion`, `Katipunan`, etc.). Preserve all Phase 3 inputs intact via non-destructive merge (`mergeVisibleOcrFields`).
  3. **Distinct Diagnostic Error Codes**: Emit `MISSING_FRONT_IMAGE`, `PROVIDER_UNAVAILABLE`, `UNREADABLE_OR_BLANK_IMAGE`, `INSUFFICIENT_VISIBLE_TEXT`, and `REQUEST_FAILED`.
  4. **Live Anthropic Model Chain**: Route all Claude Vision calls through `IClaudeMessagesClient` (`ClaudeMessagesClient`) using `claude-sonnet-4-6` primary and `claude-sonnet-5-5` automatic failover.

## ADR-ID-08: Unified Phase 2 Registration, Hidden Inputs Until Verified, Rejection Matrix, Standby Token Cache, Face-to-Gov-ID Matching & Role-Scoped AI Auto-Approval
- **Decision**:
  1. **Unified Phase 2 (Gov ID + Personal Info Merge) & Panel Decommissioning**: Collapse registration from 6 phases to 5 phases (`step=0..4`) inside `Frontend/src/LANDING_PAGE/Features/Pages/RegisterPage/RegisterPage.tsx` and 5-column `.steps` styling in `Frontend/src/LayoutStyles/register.css`: `01 Role (#phase-1-role) -> 02 ID & Info (#phase-2-id-identity) -> 03 Facial (#phase-3-facial-record) -> 04 Auth (#phase-4-credentials) -> 05 Review (#phase-5-review)`. Decommission and delete `Frontend/src/LANDING_PAGE/Features/Pages/RegisterPage/ClaudeIdOcrAutoFillPanel.tsx`, removing `#claude-id-ocr-panel`, `#btn-claude-ocr-extract`, all 14 `#ocr-field-*` inputs, `#btn-confirm-ocr-autofill`, `#badge-ocr-autofill-confirmed`, and legacy `#phase-2-id-upload` / `#phase-3-personal-info` / `#phase-6-review` selectors.
  2. **Hidden Inputs Until Background Verification/OCR Completes**: Keep `#personal-info-section` strictly unmounted (`canUnlockPersonalInfo === false`) and `#btn-phase2-next` disabled until both Front (`#front-id-input`) and Back (`#back-id-input`) Government IDs pass automatic background verification orchestrated by `Frontend/src/Hooks/useBackgroundIdVerification.ts` and surfaced by `Frontend/src/LANDING_PAGE/Features/Pages/RegisterPage/IdVerificationBanner.tsx` (`#id-verification-banner`, `#badge-id-verified-genuine`, `#badge-id-pending-manual`, `#banner-id-rejected`, `#btn-retry-id-verify`). Upon `VERIFIED_GENUINE`, reveal `#personal-info-section`, store `IdVerificationToken`, and populate visible-only fields via `mergeVisibleOcrFields` (`Frontend/src/Libs/Vision/idScanner/ai/ocrFieldUtils.ts`). Changing `select#id-type` or replacing either ID image aborts in-flight requests via `AbortController`, invalidates stale tokens, and locks `#personal-info-section` until re-verified.
  3. **Wrong-Side / Wrong-ID / Anti-Fake Rejection Matrix & Shared Evaluator**: Consolidate authenticity, side-slot, ID-family, duplicate-byte, and non-ID validation inside `IGovIdAuthenticityEvaluator` (`SharedGovIdForensicsEvaluator` in `Backend/Features/Services/Verification/GovIdForensicsContracts.cs`), shared by both `IdentityAiService` and `ClaudeAutoApproveGovIdStrategy` while preserving partial-payload test compatibility when `backBytes == null` and minimal mock JSON omits optional forensics keys. Pair local `runDualSideRegistrationPreflight` (`Frontend/src/Libs/Vision/idScanner/idScanEngine.ts`, without breaking `idRecognitionPipeline.ts`) and `ClaudeSonnetOcrProvider.ts` (`VALID_OCR_ERROR_CODES`) with `IdentityController.cs` (`POST /api/identity/ocr/extract`) to enforce exact rejection codes while keeping `#personal-info-section` unmounted: `MISSING_ID_TYPE` (`400`, added by ADR-ID-09), `MISSING_FRONT_IMAGE` (`400`), `MISSING_BACK_IMAGE` (`400`), `DUPLICATE_FRONT_BACK_IMAGE` (`422`), `WRONG_ID_SIDE_FRONT_EXPECTED` (`422`), `WRONG_ID_SIDE_BACK_EXPECTED` (`422`), `WRONG_GOVERNMENT_ID_TYPE` (`422`), `FAKE_OR_AI_GENERATED_ID` (`422`), `NON_ID_DOCUMENT` (`422`), and `UNREADABLE_OR_BLANK_IMAGE` (`422`).
  4. **Dual-Layer HMAC-SHA256 Standby Token Cache (`IDistributedCache` + SQL Server 2022 `[VerificationTokenRecords]`)**: Implement `IVerificationTokenCacheStrategy` (`HmacVerificationTokenCacheStrategy` in `Backend/Features/Services/Verification/VerificationTokenContracts.cs`) backed by `"VerificationTokens"` (`HmacSecret`, `TtlMinutes`, `FaceToIdMatchThreshold`, `AllowAutoApproveInManualMode`) in `Backend/appsettings.json` and `Backend/appsettings.Development.json` (zero `.env*` files, zero SQLite). Issue `{base64UrlPayload}.{base64UrlHmacSha256}` standby tokens stored simultaneously in `IDistributedCache` (`verification:tok:{tokenId}`) and SQL Server 2022 `[VerificationTokenRecords]` (`Backend/Features/Data/Models/VerificationTokenRecord.cs` + idempotent DDL in `DatabaseSeeder.cs`). Validate signatures in constant time via `CryptographicOperations.FixedTimeEquals`, bind `ImagePairSha256` and `PairedIdTokenId`, and atomically mark `ConsumedAtUtc` / `ConsumedByUserId` while evicting cache entries so tampering or replay fails with `400` (`INVALID_VERIFICATION_TOKEN` / `VERIFICATION_TOKEN_REPLAYED`).
  5. **Live Face-to-Gov-ID Portrait Matching**: Isolate live 4-pose camera liveness and Front ID portrait matching behind `IFaceToGovIdMatchStrategy` (`ClaudeFaceToGovIdMatchStrategy` in `GovIdForensicsContracts.cs`) via `IClaudeMessagesClient` (`claude-sonnet-4-6` primary -> `claude-sonnet-5-5` failover) wired into `POST /api/identity/biometrics/analyze-geometry`, `Frontend/src/Libs/Biometrics/claudeFacialBiometricStrategy.ts`, and `ManualFacialCapturePanel.tsx`. Mint paired `FacialVerificationToken` and render `#badge-face-id-matched` only when `IsLiveHuman == true`, `FaceToIdSimilarity >= 0.72`, and `IdVerificationToken` validates; reject spoofs (`422 LIVENESS_SPOOF_REJECTED`) or mismatches (`422 FACE_TO_ID_MISMATCH`), and keep static single-photo uploads (`#btn-upload-facial-photo`) ineligible for auto-approval tokens.
  6. **Role-Scoped AI Auto-Approval (`Civilian` & `Responder` Allowed; `LDRRMO_Admin` Blocked)**: Isolate approval policy behind `IAccountAutoApprovalStrategy` (`TokenVerifiedAutoApprovalStrategy` in `VerificationTokenContracts.cs`) injected optionally into `AuthService` (preserving existing 4-arg and 6-arg constructor signatures) and exposed via `RegisterRequest` / `RegistrationResponse` in `AuthController.cs` (`POST /api/register`). Hard-block `LDRRMO_Admin` public self-registration with `403 ROLE_FORBIDDEN` regardless of token validity. For `Civilian` and `Responder` (`FIRE`, `RHU`, `PNP`) submitting valid paired `IdVerificationToken` and `FacialVerificationToken`, atomically consume tokens, persist `AccountStatus.Verified`, `FaceVerified = true`, `AutoApprovedByAi = true`, `AutoApprovedAtUtc`, `BiometricEnrollment.EnrollmentStatus = "ACTIVE"`, `[Users]`/`[IdentityVerificationRecords]` token metadata, and SHA-256 chained `AuditLog` `"ACCOUNT_AUTO_APPROVED_AI"`. Un-tokenized registrations continue defaulting to `AccountStatus.Pending` (`PENDING_REVIEW`).
  7. **Manual Review Standby Degradation on `PROVIDER_UNAVAILABLE` (`503`)**: When Cloud AI is offline (`PROVIDER_UNAVAILABLE`, HTTP `503` with `requiresPendingManualReview: true`), `ClaudeAutoApproveGovIdStrategy` fails closed (`Approved = false`), `useBackgroundIdVerification.ts` transitions to `PENDING_MANUAL_REVIEW` (`#badge-id-pending-manual`) so `#personal-info-section` unlocks without an `IdVerificationToken`, and `ManualFacialCapturePanel.tsx` similarly degrades without a `FacialVerificationToken` so the account enters `AccountStatus.Pending` for LDRRMO Admin manual review.
- **Rationale**: Prevents unverified or mismatched ID uploads from unlocking identity entry, eliminates redundant manual OCR UI panels, centralizes fraud/authenticity heuristics in one OCP strategy shared with Standby AI, prevents single-use token forgery or replay across distributed/database layers, and automates immediate onboarding for cryptographically verified Civilian and Responder users without weakening Admin RBAC or offline availability.

## ADR-ID-09: Mandatory `Choose ID Type` Selection Gate, Gated Front/Back Upload Dropzones, Zero Silent Defaults & Backend `MISSING_ID_TYPE` (`400`) Guard
- **Decision**:
  1. **Unselected Initial State & Selectable Placeholder (`RegisterPage.tsx`)**: Initialize `idType` strictly as `useState<string>('')` (removing the silent `'philsys'` initial value). Render `<option value="">Choose ID Type</option>` as the selectable first child inside `<select id="id-type" name="idType">` followed by `visibleGovernmentIdOptions` (`GOVERNMENT_ID_OPTIONS.filter((opt) => !opt.responderOnly || selectedRole === 'Responder')`). Wrap `select#id-type` `.field` with `is-invalid` when `errors.idType` is set and render `<p className="field__error font-mono text-[10px]" id="id-type-error" role="alert">{errors.idType}</p>`.
  2. **Zero Implicit Pre-Fill Across URL Query, Role & Agency Switchers**: Never pre-fill `idType` with `'philsys'`, `'fire'`, `'police'`, `'rhu'`, or `'prc'` from initial state, URL query parameter `useEffect` (`?unit=rhu`, `?unit=pnp`, `?unit=fire`, `?unit=bfp`, `?unit=security`), `handleSelectRole`, or `handleAgencyUnitChange`. `handleAgencyUnitChange` updates only `agencyUnit`.
  3. **Gated Upload Dropzones & Hidden Personal Info (`#id-upload-locked-notice` vs `#id-upload-section`)**: Derive `isIdTypeSelected = Boolean(idType.trim() && visibleGovernmentIdOptions.some((o) => o.value === idType))`. When `!isIdTypeSelected`, strictly unmount (`count === 0`) `#id-upload-section`, `#front-id-dropzone`, `input#front-id-input`, `#back-id-dropzone`, `input#back-id-input`, `#btn-clear-both-ids`, `<IdVerificationBanner />`, and `#personal-info-section`, rendering `<div id="id-upload-locked-notice" role="status">` in Deep Burgundy styling (`register.css`). When `isIdTypeSelected === true`, mount `#id-upload-section` (`#front-id-dropzone`, `#back-id-dropzone`, `<IdVerificationBanner />`) and unlock `#personal-info-section` ONLY when `isIdTypeSelected && idVerification.canUnlockPersonalInfo` after Front & Back IDs pass background verification/OCR (`isPhase2ReadyForNext` enforces `isIdTypeSelected && idVerification.canUnlockPersonalInfo && Boolean(idFrontShot && idBackShot)`). Enforce defensive guards at the top of `handleFileUpload` and `handleDrop` to reject `!isIdTypeSelected` and set `errors.idType`.
  4. **Type-Switch & Role-Reset State Matrix**:
     - Switching between valid non-empty ID types (e.g., `'drivers' -> 'passport'`) preserves `idFrontShot`, `idBackShot`, `idFrontMeta`, and `idBackMeta` while clearing stale standby tokens (`clearStandbyToken()`, `clearStandbyRegistrationTokens()`, `resetStaleFacialTokenOnIdMutation()`) and re-running `useBackgroundIdVerification`.
     - Switching `idType` back to `''` (`Choose ID Type`) or switching Role to `'Civilian'` while holding a `responderOnly` ID (`'fire'`, `'police'`, `'rhu'`) clears uploaded shots, metadata, DOM `<input>.value` on both refs, and standby tokens (`resqtrack_standby_*`), and unmounts `#id-upload-section` and `#personal-info-section`.
     - Clicking `#btn-clear-both-ids` (`handleClearBothIds`) preserves `idType` while clearing uploaded shots, DOM `<input>.value`, and standby tokens.
  5. **Fail-Closed Hook, Vision Provider & Backend `MISSING_ID_TYPE` (`400`) Guard**:
     - `Frontend/src/Hooks/useBackgroundIdVerification.ts`: remove the `|| 'philsys'` fallback (`const idTypeClean = idType.trim();`), register `'MISSING_ID_TYPE'` in `KNOWN_ERROR_CODES` and rejection message resolver, and exit immediately to `INITIAL_VERIFICATION_STATE` (`status: 'IDLE'`, `canUnlockPersonalInfo: false`) with `persistStandbyIdToken(null)` whenever `!idTypeClean || !frontClean || !backClean`.
     - `Frontend/src/Libs/Vision/idScanner/ai/ocrFieldUtils.ts` & `ClaudeSonnetOcrProvider.ts`: add `'MISSING_ID_TYPE'` to `OcrErrorCode`, `VALID_OCR_ERROR_CODES`, and `SEMANTIC_REJECTION_ERROR_CODES`; remove `'philsys'` fallbacks in `buildMultipartFormData` and `extract`; fail closed in `extractDualSide` BEFORE any `fetch('/api/identity/ocr/extract')` call when `request.requireDualSide && !request.idType.trim()`, returning empty fields with `success: false`, `errorCode: 'MISSING_ID_TYPE'`, `confidence: 0`, and `requiresPendingManualReview: false`.
     - `Backend/Features/Api/Controllers/IdentityController.cs`: in `ExtractOcrMultipartAsync` (`POST /api/identity/ocr/extract`), immediately after verifying non-empty `frontBytes`, enforce `if (IsTruthyFlag(requireDualSide) && string.IsNullOrWhiteSpace(idType)) return BadRequest(BuildFailureOcrDto("MISSING_ID_TYPE", ...));` before invoking `aiService.ExtractIdOcrAsync`, and map `"MISSING_ID_TYPE"` alongside `"MISSING_FRONT_IMAGE"` / `"MISSING_BACK_IMAGE"` to `BadRequest(result)` in `MapOcrActionResult`.
  6. **Two-Tier Test Harness Contract**: Keep production `ClaudeMessagesClient` targeting live `https://api.anthropic.com/v1/messages` (`Claude:Endpoint`) with zero test bypasses; route deterministic E2E suites in `Testing/Frontend/` through `Testing/Frontend/fixtures/anthropicTestWireServer.ts` (`startAnthropicTestWireServer()`) via `Claude__Endpoint` inside `Testing/Frontend/fixtures/e2eServerHarness.ts`.
- **Rationale**: Eliminates silent wrong-document misclassifications caused by implicit `'philsys'` or unit-derived defaults, guarantees users explicitly select their Government ID document type before uploading Front/Back images, ensures invalid/unselected requests fail closed on both client and server (`400 MISSING_ID_TYPE`) before incurring AI/OCR calls, and prevents stale uploads or standby tokens from leaking across role/type resets.
